# 프로세스 관리

- 리눅스마스터 1급 필기 대비 이론 — 프로세스 개념·상태·시그널·우선순위·스케줄링
- 시그널 번호표, cron 필드 순서, nice 범위가 최빈출 → 숫자 단위 암기 필요

---

## 1. 프로세스 개념

### 1-1. 기본 용어

| 용어 | 의미 |
| --- | --- |
| 프로세스 | 실행 중인 프로그램 (메모리에 적재된 능동적 개체) |
| 프로그램 | 디스크에 저장된 실행 파일 (수동적 개체) |
| PID | Process ID — 프로세스 고유 번호 |
| PPID | Parent PID — 부모 프로세스 번호 |
| 데몬 | 백그라운드 상주 서비스 프로세스 (`httpd`, `sshd` 등) |

- PID 1 = 최초 프로세스 — SysV `init` 또는 systemd (`systemd`) → 모든 프로세스의 조상
- PID 0 = 스케줄러(swapper), 커널 내부 프로세스

### 1-2. 프로세스 생성 방식

| 방식 | 동작 | 특징 |
| --- | --- | --- |
| `fork()` | 부모 복제 → 자식 생성 | 부모·자식 별개 PID, 동일 코드 실행 (PID 2개) |
| `exec()` | 현재 프로세스를 새 프로그램으로 **교체** | 새 PID 생성 없음 (PID 유지) |
| fork + exec | 자식 생성 후 그 자식을 다른 프로그램으로 교체 | 셸의 일반적 명령 실행 방식 |

- `fork` = 복제(자기 자신 그대로), `exec` = 덮어쓰기(코드 영역 교체)가 대비 출제 포인트
- 부팅 흐름: 커널 → PID 1(`init`/`systemd`) → 이하 서비스·로그인 셸 순차 생성

## 2. 프로세스 상태

### 2-1. 상태 코드 (`ps` STAT 열)

| 코드 | 상태 | 설명 |
| --- | --- | --- |
| `R` | 실행(Running) | CPU 점유 중 또는 실행 대기 큐 |
| `S` | 대기(Sleep) | **인터럽트 가능** 대기 (시그널로 깨어남) |
| `D` | 대기(Uninterruptible) | **인터럽트 불가** 대기 (주로 I/O), `kill` 로 종료 불가 |
| `T` | 정지(Stopped) | `Ctrl+Z` 또는 STOP 시그널로 일시정지 |
| `Z` | 좀비(Zombie) | 종료됐으나 부모가 회수(wait) 안 한 상태 |

- 부가 기호: `s`(세션 리더) · `+`(포그라운드 그룹) · `l`(멀티스레드) · `<`(높은 우선순위) · `N`(낮은 우선순위)

### 2-2. 좀비 vs 고아 프로세스 (빈출 대비)

| 구분 | 좀비(Zombie) | 고아(Orphan) |
| --- | --- | --- |
| 상태 | 자식이 **먼저 종료** | 부모가 **먼저 종료** |
| 원인 | 부모가 자식 종료 상태 미회수(wait 미호출) | 부모 프로세스 비정상 종료 |
| PPID | 원래 부모 유지 (좀비로 잔존) | PID 1(`init`/`systemd`)로 재지정 |
| 처리 | 부모가 wait 하거나 부모 종료 시 소멸 | `init`/`systemd`가 입양 후 회수 |
| 자원 | 프로세스 테이블 항목만 점유 (실제 메모리 회수됨) | 정상 실행 지속 가능 |

- 좀비는 `kill -9` 로 제거 불가 → 부모를 종료해야 `init`이 회수
- 고아는 문제 프로세스가 아님 (입양되어 정상 동작)

## 3. 데몬 프로세스

| 방식 | 동작 | 특징 |
| --- | --- | --- |
| standalone | 부팅 시 상주하며 요청 직접 대기 | 응답 빠름, 메모리 상시 점유 (`httpd`, `sshd`, `named`) |
| `xinetd`(inetd) | 슈퍼데몬이 요청 수신 후 해당 데몬 기동 | 메모리 절약, 최초 응답 지연 (`telnet`, `tftp`, `rsync`) |

- `xinetd` 설정: `/etc/xinetd.conf`, 서비스별 `/etc/xinetd.d/<서비스>`
- 접근 제어를 TCP Wrapper(`/etc/hosts.allow`·`hosts.deny`)와 연동 → [[system-security]]
- 자주 켜지는 서비스 = standalone, 드물게 쓰는 서비스 = xinetd 방식이 선택 기준

## 4. 포그라운드 / 백그라운드 · 잡 제어

| 조작 | 동작 |
| --- | --- |
| `명령 &` | 백그라운드 실행 |
| `Ctrl+Z` | 포그라운드 작업 **일시정지**(T 상태) → 백그라운드로 이동 |
| `jobs` | 현재 셸의 잡 목록 (작업번호·상태) |
| `fg %n` | n번 잡을 포그라운드로 전환 |
| `bg %n` | 정지된 n번 잡을 백그라운드에서 재개 |
| `Ctrl+C` | 포그라운드 작업 종료(SIGINT) |

- `nohup 명령 &` : 로그아웃(SIGHUP) 후에도 계속 실행, 출력은 `nohup.out` 으로 → [[nohup]]
- `disown` : 실행 중인 잡을 셸의 잡 테이블에서 제거 → 로그아웃 영향 배제
- 잡 번호(`%1`)와 PID 는 다름 — `jobs -l` 로 PID 병기 확인

## 5. 시그널 (Signal)

### 5-1. 주요 시그널 번호표 (최빈출)

| 번호 | 이름 | 기본 동작 | 설명 |
| --- | --- | --- | --- |
| 1 | SIGHUP | 종료/재시작 | 터미널 연결 끊김 / 데몬 설정 재읽기 관용 |
| 2 | SIGINT | 종료 | 인터럽트 (`Ctrl+C`) |
| 3 | SIGQUIT | 종료+코어덤프 | 종료 (`Ctrl+\`) |
| 9 | SIGKILL | **강제 종료** | 무시·차단 불가, 즉시 종료 |
| 15 | SIGTERM | 종료 | **기본 시그널**, 정상 종료 요청 (차단 가능) |
| 17 | SIGCHLD | 무시 | 자식 상태 변화 통지 |
| 18 | SIGCONT | 재개 | 정지된 프로세스 재개 |
| 19 | SIGSTOP | 정지 | **강제 정지**, 무시·차단 불가 |
| 20 | SIGTSTP | 정지 | 터미널 정지 (`Ctrl+Z`) |

- `SIGKILL`(9)·`SIGSTOP`(19)만 **무시·핸들러 등록 불가** → 확실한 종료·정지
- `kill` 기본값은 15(SIGTERM), `-9`(SIGKILL)는 최후 수단
- 번호 vs 이름 매핑(특히 9/15/1/2/19/20)이 단골 함정

### 5-2. 시그널 전송 명령

| 명령 | 대상 지정 | 예시 |
| --- | --- | --- |
| `kill` | **PID** | `kill -9 1234` / `kill -HUP 1234` → [[kill]] |
| `killall` | **프로세스 이름** | `killall -9 httpd` |
| `pkill` | 이름·패턴·속성 | `pkill -u user1 sshd` → [[pkill]] |

- `kill -l` : 시그널 목록 조회
- 프로세스 검색은 [[pgrep]] (`pgrep -u user1 -l`)와 조합

## 6. 프로세스 우선순위

| 항목 | 범위 | 의미 |
| --- | --- | --- |
| NI (nice) | **-20 ~ 19** | 사용자 지정 우선순위 값, **작을수록 높은 우선순위** |
| PRI | 커널 계산값 | 실제 스케줄링 우선순위 (NI 반영) |

- 기본 NI = 0
- `nice -n 10 명령` : 시작 시 우선순위 부여 (값 클수록 양보)
- `renice -n -5 -p 1234` : **실행 중** 프로세스 우선순위 변경
- 음수(NI < 0) 설정은 **root 만** 가능, 일반 사용자는 값 상향(양보)만 허용
- `top` 의 `NI`·`PR` 열에서 확인, `top` 내에서 `r` 키로 renice

## 7. 프로세스 조회 명령

### 7-1. `ps` 옵션 계열 (빈출 대비)

| 계열 | 형식 | 예시 |
| --- | --- | --- |
| BSD | 하이픈 없음 | `ps aux` (a 전체 터미널 / u 사용자 형식 / x 터미널 없는 것 포함) |
| System V | 하이픈 사용 | `ps -ef` (e 전체 / f 풀 포맷) |

- `ps aux` ↔ `ps -ef` 결과 유사, 옵션 표기 방식이 대비 포인트 → [[ps]]
- `ps -ejH` / `ps axjf` : 트리 형태 출력

### 7-2. 기타 조회 도구

| 명령 | 용도 |
| --- | --- |
| `top` | 실시간 프로세스·자원 모니터링 (CPU·MEM·load) |
| `pstree` | 프로세스 계층(부모-자식) 트리 표시 |
| `pgrep` | 조건(이름·사용자)에 맞는 PID 검색 → [[pgrep]] |
| `lsof` | 프로세스가 연 파일·소켓 조회 → [[lsof]] |

- `top` 상호작용 키: `k`(kill) · `r`(renice) · `M`(메모리순) · `P`(CPU순) · `1`(코어별 표시)

## 8. 스케줄링 — cron / at / anacron

### 8-1. cron (반복 예약)

- 데몬 `crond`, 사용자 예약 편집: `crontab -e` → [[crontab]]
- crontab 필드 = **5개** + 명령

```
# ┌─ 분(0-59)
# │ ┌─ 시(0-23)
# │ │ ┌─ 일(1-31)
# │ │ │ ┌─ 월(1-12)
# │ │ │ │ ┌─ 요일(0-7, 0·7=일요일)
# │ │ │ │ │
  30 2 * * 1  /usr/local/bin/backup.sh    # 매주 월요일 02:30
  */10 * * * * /usr/bin/check.sh           # 10분마다
  0 0 1 * *   /usr/bin/monthly.sh          # 매월 1일 00:00
```

- 특수문자: `*`(전체) · `,`(나열 `1,15`) · `-`(범위 `1-5`) · `/`(간격 `*/10`)
- 관련 파일/디렉터리

| 경로 | 용도 |
| --- | --- |
| `/etc/crontab` | 시스템 전역 crontab (사용자 필드 추가됨) |
| `/etc/cron.d/` | 패키지·서비스별 cron 조각 파일 |
| `/etc/cron.daily/` · `cron.weekly/` · `cron.monthly/` · `cron.hourly/` | 주기별 스크립트 디렉터리 |
| `/var/spool/cron/` | 사용자별 crontab 저장 위치 |
| `/etc/cron.allow` · `/etc/cron.deny` | 사용자별 cron 사용 허용·거부 |

- `/etc/crontab` 형식은 사용자 필드가 하나 더 있음 (`분 시 일 월 요일 사용자 명령`) — 사용자 crontab(5필드)과 구분

### 8-2. at (1회성 예약)

- 데몬 `atd`, 지정 시각에 **한 번만** 실행
- `at 5pm tomorrow` / `at now + 2 hours` 후 명령 입력, `Ctrl+D` 로 등록
- `atq` (대기 목록) · `atrm <번호>` (삭제)
- `/etc/at.allow` · `/etc/at.deny` 로 사용자 제어
- 1회성 → cron(반복)과 용도 대비

### 8-3. anacron

- 상시 가동하지 않는 시스템(노트북 등)에서 **누락된 주기 작업 보정 실행**
- cron 은 지정 시각에 꺼져 있으면 건너뜀 → anacron 은 부팅 후 밀린 작업 수행
- 설정: `/etc/anacrontab` — `주기(일) 지연(분) 작업ID 명령`

## 9. 시스템 부하 (load average)

- `uptime` : 가동 시간·접속자 수·load average 3개 값 출력

```
 14:20:01 up 3 days,  2:11,  2 users,  load average: 0.15, 0.30, 0.45
                                                     └1분  └5분  └15분 평균
```

- load average = 실행 중(R) + 대기(D) 프로세스의 평균 개수 (CPU 대기 큐 길이)
- 판단 기준: 값이 **코어 수** 근처면 포화, 초과 시 과부하
  - 예: 4코어에서 load 4.0 ≈ 100% 활용
- `top` 상단·`w` 에서도 동일 값 확인 가능
