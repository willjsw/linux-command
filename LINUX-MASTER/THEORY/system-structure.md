# 리눅스 시스템의 이해

- 리눅스마스터 1급 필기 대비 이론 — 파일시스템 계층·파일 유형·inode·셸·X 윈도·하드웨어
- FHS 디렉터리 용도, 하드링크 vs 심볼릭링크, 셸 초기화 파일 로드 순서가 최빈출 → 표 단위 암기 필요

---

## 1. 파일시스템 계층 표준 (FHS)

### 1-1. 주요 디렉터리 용도 (최빈출)

| 디렉터리 | 용도 |
| --- | --- |
| `/` | 루트 — 전체 계층의 최상위 |
| `/bin` | 필수 사용자 명령 바이너리 (`ls`, `cp` 등) — 단일 사용자 모드에서도 사용 |
| `/sbin` | 시스템 관리용 바이너리 (`fdisk`, `ifconfig` 등) — 주로 root |
| `/etc` | 시스템 전역 설정 파일 (텍스트) |
| `/var` | 가변 데이터 — 로그(`/var/log`)·메일·스풀·캐시 |
| `/usr` | 사용자 응용 프로그램·라이브러리 (읽기 전용 성격, 2차 계층) |
| `/home` | 일반 사용자 홈 디렉터리 |
| `/root` | root 계정 전용 홈 디렉터리 |
| `/proc` | 프로세스·커널 정보 가상 파일시스템 (메모리 기반) |
| `/sys` | 커널·장치 정보 가상 파일시스템 (sysfs) |
| `/dev` | 장치 파일 (블록·문자 장치) |
| `/tmp` | 임시 파일 — 재부팅 시 삭제, Sticky Bit 설정 |
| `/boot` | 커널 이미지·initramfs·부트로더 파일 (GRUB) |
| `/lib`, `/lib64` | 필수 공유 라이브러리·커널 모듈 |
| `/opt` | 추가 응용 소프트웨어 패키지 (서드파티) |
| `/mnt` | 임시 수동 마운트 지점 |
| `/media` | 이동식 매체(USB·CD) 자동 마운트 지점 |

- `/proc`·`/sys` 는 디스크가 아닌 **메모리 기반 가상 파일시스템** → 함정 포인트
- `/bin`·`/sbin`·`/lib` 은 부팅 초기 필수 → 별도 파티션 분리 지양
- 마운트·파티션 구조 상세는 [[disk-device]] 참조

## 2. 파일 유형

### 2-1. 7가지 파일 유형 (`ls -l` 첫 문자)

| 표기 | 유형 | 설명 |
| --- | --- | --- |
| `-` | 일반 파일 | 텍스트·바이너리·데이터 |
| `d` | 디렉터리 | 파일 목록을 담는 특수 파일 |
| `l` | 심볼릭 링크 | 다른 파일 경로를 가리키는 링크 |
| `b` | 블록 장치 | 블록 단위 입출력 (디스크: `/dev/sda`) |
| `c` | 문자 장치 | 문자 단위 입출력 (터미널: `/dev/tty`) |
| `s` | 소켓 | 프로세스 간 양방향 통신 종단점 |
| `p` | 파이프(FIFO) | 이름 있는 파이프, 프로세스 간 단방향 통신 |

- 유형 확인: [[ls]] `-l`, 내용 기반 판별: [[file]], 메타데이터: [[stat]]

### 2-2. 하드링크 vs 심볼릭 링크 (최빈출)

| 구분 | 하드링크 | 심볼릭(소프트) 링크 |
| --- | --- | --- |
| 생성 | `ln 원본 링크` | `ln -s 원본 링크` |
| inode | 원본과 **동일 inode 공유** | **새 inode** — 경로 문자열 저장 |
| 링크 수 | 원본 링크 수 증가 | 원본 링크 수 불변 |
| 원본 삭제 시 | 데이터 유지 (링크 수>0) | 링크 깨짐(dangling) |
| 파일시스템 경계 | 넘을 수 없음 | 넘을 수 있음 |
| 디렉터리 대상 | 불가 (일반적) | 가능 |

- 하드링크는 동일 inode → 두 이름이 동등한 실체를 가리킴
- 심볼릭 링크는 경로 포인터 → `ls -l` 에서 `링크 -> 원본` 표시

### 2-3. 장치 파일

- 블록 장치(`b`): 버퍼 통해 블록 단위 접근 — 디스크·파티션
- 문자 장치(`c`): 버퍼 없이 문자 단위 접근 — 터미널·키보드
- `ls -l /dev` 에서 크기 자리에 **주 번호(major)·부 번호(minor)** 표시
  - major = 장치 드라이버 식별, minor = 개별 장치 식별

## 3. inode

- 파일 1개당 1개 — 파일의 **메타데이터** 저장 구조
- 저장 정보: 파일 유형·권한·소유자(UID/GID)·크기·타임스탬프(atime/mtime/ctime)·링크 수·**데이터 블록 포인터**
- **파일 이름은 inode 에 없음** → 디렉터리가 `이름↔inode 번호` 매핑을 보유 (함정 포인트)
- inode 번호 확인: `ls -i`, 상세 메타데이터: [[stat]]
- 하드링크 = 같은 inode 번호를 여러 이름이 참조 → 링크 수(link count) 증가
- inode 고갈 시 디스크 여유 공간이 있어도 파일 생성 불가 (`df -i` 로 점검)
- 권한·소유권 상세는 [[user-permission]] 참조

## 4. SHELL

### 4-1. 셸 종류

| 셸 | 특징 |
| --- | --- |
| `sh` (Bourne) | 최초의 유닉스 표준 셸, 스크립트 기본 |
| `bash` (Bourne Again) | 리눅스 기본 셸, sh 확장 (history·자동완성) |
| `csh` | C 언어 문법 유사, 대화형 기능 도입 |
| `tcsh` | csh 확장 (명령 편집·완성) |
| `ksh` (Korn) | sh 호환 + csh 기능 결합 |
| `zsh` | 강력한 자동완성·플러그인, ksh/bash 상위 호환 성격 |

- 로그인 셸 지정: `/etc/passwd` 7번째 필드, 변경: `chsh`
- 셸 위치 확인: [[which]], 사용 가능 셸 목록: `/etc/shells`

### 4-2. 초기화 파일 로드 순서 (최빈출)

| 파일 | 범위 | 적용 시점 |
| --- | --- | --- |
| `/etc/profile` | 전역 | 로그인 셸 진입 시 (전 사용자) |
| `/etc/profile.d/*.sh` | 전역 | `/etc/profile` 에서 호출 |
| `~/.bash_profile` | 개인 | 로그인 셸 — 사용자별 |
| `~/.bash_login`, `~/.profile` | 개인 | `.bash_profile` 없을 때 대체 |
| `~/.bashrc` | 개인 | 비로그인(대화형) 셸 진입 시, 통상 `.bash_profile` 이 호출 |
| `~/.bash_logout` | 개인 | 로그아웃 시 실행 |

```
로그인 셸:  /etc/profile → ~/.bash_profile → (~/.bashrc → /etc/bashrc)
비로그인 셸: ~/.bashrc → /etc/bashrc
```

- 로그인 셸은 profile 계열, 비로그인 대화형 셸은 bashrc 계열이 진입점 → 출제 포인트

### 4-3. 환경변수 vs 셸 변수

| 구분 | 환경변수 | 셸(지역) 변수 |
| --- | --- | --- |
| 범위 | 자식 프로세스로 상속 | 현재 셸에만 유효 |
| 등록 | `export VAR=값` | `VAR=값` |
| 조회 | `env`, `printenv` | `set` |

- 환경변수 전체 조회: [[env]]

| 환경변수 | 의미 |
| --- | --- |
| `PATH` | 명령 탐색 경로 목록 (`:` 구분) |
| `HOME` | 사용자 홈 디렉터리 |
| `PS1` | 기본 프롬프트 문자열 |
| `PS2` | 보조 프롬프트 (명령 연속 입력) |
| `SHELL` | 로그인 셸 경로 |
| `LANG` | 기본 로케일·언어 |
| `PWD` | 현재 작업 디렉터리 |
| `USER` | 현재 사용자명 |

### 4-4. 메타문자·리다이렉션·파이프

| 기호 | 기능 |
| --- | --- |
| `>` | 표준출력 리다이렉션 (덮어쓰기) |
| `>>` | 표준출력 리다이렉션 (이어쓰기) |
| `<` | 표준입력 리다이렉션 |
| `2>` | 표준에러(stderr) 리다이렉션 |
| `&>` | 표준출력 + 표준에러 함께 리다이렉션 |
| `|` | 파이프 — 앞 명령 출력을 뒤 명령 입력으로 연결 |
| `;` | 명령 순차 실행 |
| `&&` / `\|\|` | 앞 명령 성공/실패 시에만 다음 실행 |
| `*`, `?`, `[]` | 와일드카드 (파일명 확장) |
| `&` | 백그라운드 실행 |

- 표준 스트림 번호: stdin=0, stdout=1, stderr=2

### 4-5. alias·history

- `alias ll='ls -l'` : 명령 별칭 등록, `unalias ll` : 해제, `alias` : 목록 조회
- 영구 적용: `~/.bashrc` 에 등록
- `history` : 명령 이력 조회, `!!` (직전 명령), `!n` (n번 명령 재실행)
- 이력 파일: `~/.bash_history`, 크기 변수: `HISTSIZE`(메모리)·`HISTFILESIZE`(파일)

## 5. X 윈도

### 5-1. 구조 (역방향 클라이언트-서버)

- **X 서버**: 사용자 앞 로컬 머신 — 디스플레이·키보드·마우스 등 입출력 하드웨어 제어
- **X 클라이언트**: 응용 프로그램 — 화면 출력을 서버에 요청
- 서버가 사용자 측, 클라이언트가 응용 측 → 일반 서버-클라이언트와 **반대** (함정 포인트)
- 통신 규약: **X 프로토콜** (네트워크 투명성 — 원격 실행 가능)

### 5-2. 관련 요소

| 요소 | 설명 |
| --- | --- |
| Xlib | X 프로토콜 저수준 C 라이브러리 |
| XFree86 | 과거 오픈소스 X 구현 (라이선스 문제로 분기) |
| X.org | XFree86 후속 표준 구현 (현행) |
| 디스플레이 매니저 | 그래픽 로그인 화면 — `gdm`(GNOME)·`kdm`(KDE)·`xdm`(기본) |
| 데스크톱 환경 | 통합 GUI — GNOME, KDE, Xfce, LXDE |
| 윈도 매니저 | 창 배치·장식 관리 (Mutter, KWin 등) |

### 5-3. DISPLAY 변수

- 형식: `호스트:디스플레이번호.스크린번호` (예: `:0.0`, `192.168.0.5:0`)
- 로컬 기본값 `:0` — X 클라이언트가 출력할 X 서버 지정
- 원격 GUI 전달: `export DISPLAY=원격:0` 또는 `ssh -X` (X 포워딩)

## 6. 하드웨어 정보

### 6-1. /proc 기반 정보 (최빈출)

| 경로 | 내용 |
| --- | --- |
| `/proc/cpuinfo` | CPU 모델·코어 수·클럭·플래그 |
| `/proc/meminfo` | 메모리 총량·가용량·스왑 |
| `/proc/interrupts` | IRQ 인터럽트 사용 현황 |
| `/proc/ioports` | I/O 포트 주소 할당 |
| `/proc/partitions` | 디스크 파티션 목록 |
| `/proc/<PID>/` | 개별 프로세스 정보 |

- `/proc` 는 커널이 실시간 생성하는 가상 파일 → 디스크 미점유

### 6-2. 장치 인식·조회 도구

| 도구 | 용도 |
| --- | --- |
| `lscpu` | CPU 아키텍처 요약 |
| `free` | 메모리 사용량 (`meminfo` 요약) |
| `lspci` | PCI 장치 목록 |
| `lsusb` | USB 장치 목록 |
| `lsblk` | 블록 장치(디스크) 트리 |
| `dmesg` | 부팅·장치 인식 커널 메시지 |

- udev(`/dev` 동적 관리)가 장치 연결 시 장치 파일 자동 생성
- 디스크 장치·파티션 상세는 [[disk-device]] 참조
