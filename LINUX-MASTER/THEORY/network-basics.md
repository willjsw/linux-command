# 네트워크의 이해

- 리눅스마스터 1급 필기 대비 이론 — OSI 7계층·TCP/IP·IP 주소 체계·서브네팅·프로토콜·설정 파일
- **서브넷 계산**(넷마스크↔프리픽스↔호스트 수)과 **포트·프로토콜 매칭**이 계산·암기 최빈출

---

## 1. OSI 7계층 (최우선 암기)

| 계층 | 이름 | 역할 | 대표 프로토콜 | PDU(데이터 단위) | 대표 장비 |
| --- | --- | --- | --- | --- | --- |
| 7 | 응용(Application) | 사용자 서비스 인터페이스 | HTTP, FTP, SMTP, DNS, Telnet | 데이터(Data) | 게이트웨이 |
| 6 | 표현(Presentation) | 인코딩·암호화·압축 | SSL/TLS, JPEG, ASCII | 데이터 | — |
| 5 | 세션(Session) | 연결 설정·유지·동기화 | NetBIOS, RPC | 데이터 | — |
| 4 | 전송(Transport) | 종단 간 신뢰성·흐름 제어 | **TCP, UDP** | 세그먼트(Segment) | L4 스위치 |
| 3 | 네트워크(Network) | 논리 주소·경로 결정(라우팅) | **IP**, ICMP, ARP, RARP | 패킷(Packet) | 라우터, L3 스위치 |
| 2 | 데이터링크(Data Link) | 인접 노드 간 전송·오류 제어 | Ethernet, PPP, MAC | 프레임(Frame) | 스위치, 브리지 |
| 1 | 물리(Physical) | 비트 전기 신호 전송 | RS-232, 케이블 규격 | 비트(Bit) | 리피터, 허브 |

- 주소 계층 구분이 함정: **2계층 = MAC(물리 주소)**, **3계층 = IP(논리 주소)**
- 장비 대응: 물리=리피터/허브, 데이터링크=스위치/브리지, 네트워크=라우터
- 암기: "**A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing" (7→1)
- ARP 는 관례상 2·3계층 경계 — 논리(IP)↔물리(MAC) 변환 담당

## 2. TCP/IP 4계층 모델

| TCP/IP 4계층 | 대응 OSI 계층 | 대표 프로토콜 |
| --- | --- | --- |
| 응용(Application) | 5·6·7 (세션·표현·응용) | HTTP, FTP, SMTP, DNS, Telnet, SSH |
| 전송(Transport) | 4 (전송) | TCP, UDP |
| 인터넷(Internet) | 3 (네트워크) | IP, ICMP, ARP, RARP, IGMP |
| 네트워크 접근(Network Access) | 1·2 (물리·데이터링크) | Ethernet, PPP, ARP |

- 4계층 모델은 실제 인터넷 구현 기준 — OSI 는 참조 모델(개념)
- 응용 계층이 OSI 상위 3개(5·6·7)를 통합하는 점이 대응 문제 핵심

## 3. 전송 계층 — TCP vs UDP

### 3-1. 비교표 (최빈출)

| 구분 | TCP | UDP |
| --- | --- | --- |
| 연결 방식 | 연결지향(connection-oriented) | 비연결(connectionless) |
| 신뢰성 | 높음 (재전송·순서 보장·흐름 제어) | 낮음 (보장 없음) |
| handshake | 3-way handshake 로 연결 수립 | 없음 (즉시 전송) |
| 헤더 크기 | 20바이트(옵션 시 최대 60) | 8바이트(고정) |
| 전송 단위 | 세그먼트(Segment) | 데이터그램(Datagram) |
| 속도 | 상대적 느림 | 빠름 |
| 용도 | HTTP, FTP, SMTP, SSH, Telnet | DNS, DHCP, TFTP, SNMP, 스트리밍, VoIP |

- UDP 는 헤더 8바이트 고정(출발·목적 포트, 길이, 체크섬 각 2바이트)
- DNS 는 질의 UDP 53, 존 전송(zone transfer)은 TCP 53 → 양쪽 모두 사용

### 3-2. 3-way handshake (연결 수립)

```
클라이언트                     서버
    | ---- SYN ----------------> |   (1) 연결 요청, seq=x
    | <--- SYN + ACK ----------- |   (2) 수락+응답, seq=y, ack=x+1
    | ---- ACK ----------------> |   (3) 확인, ack=y+1  → 연결 성립(ESTABLISHED)
```

### 3-3. 4-way handshake (연결 종료)

```
    | ---- FIN ----------------> |   (1) 종료 요청
    | <--- ACK ----------------- |   (2) 확인
    | <--- FIN ----------------- |   (3) 서버측 종료 요청
    | ---- ACK ----------------> |   (4) 확인 → TIME_WAIT 후 종료
```

- 연결 상태 확인은 [[ss]] (구 `netstat`) — `SYN_SENT`, `ESTABLISHED`, `TIME_WAIT` 등

## 4. IPv4 주소 체계

### 4-1. 클래스별 범위 (최빈출)

| 클래스 | 첫 옥텟 범위 | 기본 넷마스크 | 프리픽스 | 용도 |
| --- | --- | --- | --- | --- |
| A | 0 ~ 127 | 255.0.0.0 | /8 | 대규모 (호스트 약 1,600만) |
| B | 128 ~ 191 | 255.255.0.0 | /16 | 중규모 (호스트 약 6.5만) |
| C | 192 ~ 223 | 255.255.255.0 | /24 | 소규모 (호스트 254) |
| D | 224 ~ 239 | — | — | 멀티캐스트 |
| E | 240 ~ 255 | — | — | 연구·예약 |

- 클래스 판별은 **첫 옥텟의 상위 비트**: A=`0`, B=`10`, C=`110`, D=`1110`, E=`1111`
- D(224~239)는 멀티캐스트, E(240~255)는 예약 → 호스트 할당 불가

### 4-2. 특수 대역 (함정 단골)

| 대역 | 이름 | 용도 |
| --- | --- | --- |
| `10.0.0.0/8` | 사설(A) | 내부망 전용 (라우팅 안 됨) |
| `172.16.0.0/12` | 사설(B) | 172.16.0.0 ~ 172.31.255.255 |
| `192.168.0.0/16` | 사설(C) | 192.168.0.0 ~ 192.168.255.255 |
| `169.254.0.0/16` | 링크로컬(APIPA) | DHCP 실패 시 자동 할당 — **사설 아님** |
| `127.0.0.0/8` | 루프백 | 자기 자신 (`127.0.0.1` = localhost) |
| `0.0.0.0` | 미지정 | 전체·기본 경로 지정 |

- 사설 IP 3대역 = **10/8, 172.16/12, 192.168/16** (RFC 1918)
- `172.16/12` 는 172.16 ~ **172.31** 까지 (172.32 는 공인) — 범위 함정 주의
- `169.254.0.0/16`(APIPA)은 사설 대역이 아님 → 오답 유도 최빈출

## 5. 서브네팅

### 5-1. 넷마스크 ↔ 프리픽스 ↔ 호스트 수 (계산 필수 암기)

| 프리픽스 | 넷마스크 | 마지막 옥텟(2진) | 서브넷당 호스트 수 |
| --- | --- | --- | --- |
| /24 | 255.255.255.0 | `00000000` | 2^8 − 2 = 254 |
| /25 | 255.255.255.128 | `10000000` | 2^7 − 2 = 126 |
| /26 | 255.255.255.192 | `11000000` | 2^6 − 2 = 62 |
| /27 | 255.255.255.224 | `11100000` | 2^5 − 2 = 30 |
| /28 | 255.255.255.240 | `11110000` | 2^4 − 2 = 14 |

- 사용 가능 호스트 수 = **2^(호스트 비트) − 2** (네트워크 주소·브로드캐스트 주소 제외)
- 넷마스크 옥텟 값 암기: 128 → 192 → 224 → 240 → 248 → 252 → 254 → 255

### 5-2. 서브넷 분할 예제

- `/24` 를 `/26` 으로 분할 (2비트 차용)
	- 서브넷 개수 = 2^2 = **4개**
	- 서브넷당 호스트 = 2^6 − 2 = **62개**
	- 블록 크기 = 256 − 192 = 64 → 네트워크: `.0`, `.64`, `.128`, `.192`
- `/24` 를 `/28` 로 분할 (4비트 차용)
	- 서브넷 개수 = 2^4 = **16개**, 서브넷당 호스트 = 2^4 − 2 = **14개**
- 역산 예: 호스트 250대 수용 → `/24`(254) 필요, `/25`(126)는 부족

## 6. IPv6 개요

- 주소 길이 **128비트** (IPv4 는 32비트) — 주소 고갈 문제 해결
- 표기: 16비트씩 8그룹을 `:` 로 구분한 16진수
	- 예: `2001:0db8:0000:0000:0000:ff00:0042:8329`
	- 축약: 각 그룹 앞 `0` 생략, 연속 `0` 그룹은 `::` 로 한 번만 축약
	- → `2001:db8::ff00:42:8329`
- IPv4 대비 특징

| 항목 | IPv4 | IPv6 |
| --- | --- | --- |
| 주소 길이 | 32비트 | 128비트 |
| 표기 | 10진수 점 표기 | 16진수 콜론 표기 |
| 주소 자동 설정 | DHCP 필요 | 자동 구성(SLAAC) 지원 |
| 보안 | 선택(IPsec) | IPsec 기본 내장 |
| 브로드캐스트 | 있음 | 없음 (멀티캐스트·애니캐스트로 대체) |

## 7. 주요 포트 번호 (최빈출)

- Well-known 포트: **0 ~ 1023**, 등록 포트: 1024 ~ 49151, 동적 포트: 49152 ~ 65535

| 포트 | 프로토콜/서비스 | 전송 계층 |
| --- | --- | --- |
| 20 / 21 | FTP (데이터 / 제어) | TCP |
| 22 | SSH | TCP |
| 23 | Telnet | TCP |
| 25 | SMTP (메일 전송) | TCP |
| 53 | DNS | UDP/TCP |
| 67 / 68 | DHCP (서버 / 클라이언트) | UDP |
| 80 | HTTP | TCP |
| 110 | POP3 (메일 수신·삭제) | TCP |
| 143 | IMAP (메일 수신·보관) | TCP |
| 443 | HTTPS | TCP |
| 3306 | MySQL / MariaDB | TCP |

- 포트↔프로토콜 매핑 정본: `/etc/services`
- 서비스별 설정·데몬 상세는 [[network-service]]

## 8. 주요 프로토콜

| 프로토콜 | 계층 | 역할 |
| --- | --- | --- |
| ARP | 네트워크(3) | **IP → MAC** 주소 변환 |
| RARP | 네트워크(3) | **MAC → IP** 주소 변환 (역방향) |
| ICMP | 네트워크(3) | 오류·상태 통보 — `ping`·`traceroute` 기반 |
| IGMP | 네트워크(3) | 멀티캐스트 그룹 관리 |
| DNS | 응용(7) | 도메인 이름 ↔ IP 변환 |
| DHCP | 응용(7) | IP·게이트웨이·DNS 자동 할당 |

- ICMP 도달 진단은 [[ping]] — echo request/reply 사용
- DHCP 할당 절차: **DORA** (Discover → Offer → Request → Ack)
- ARP 캐시 조회는 `ip neigh` (구 `arp -a`) → [[ip]]

## 9. 네트워크 설정 파일

| 파일 | 역할 |
| --- | --- |
| `/etc/sysconfig/network-scripts/ifcfg-*` | RHEL 계열 인터페이스 설정 (구식, 정적 IP·게이트웨이) |
| `/etc/resolv.conf` | DNS 서버 지정 (`nameserver 8.8.8.8`) |
| `/etc/hosts` | 정적 호스트명 ↔ IP 매핑 (DNS 우선 조회) |
| `/etc/nsswitch.conf` | 이름 해석 순서 (`hosts: files dns` = hosts 파일 우선) |
| `/etc/services` | 서비스명 ↔ 포트·프로토콜 매핑 |
| `/etc/protocols` | 프로토콜명 ↔ 번호 매핑 |

- `ifcfg-*` 주요 항목: `BOOTPROTO`(static/dhcp), `IPADDR`, `NETMASK`(또는 `PREFIX`), `GATEWAY`, `DNS1`, `ONBOOT`(부팅 시 활성)
- RHEL 8+ 는 NetworkManager 가 표준 → [[nmcli]] 로 관리(`ifcfg` 대체)
- `/etc/nsswitch.conf` 의 `hosts` 항목 순서가 조회 우선순위 결정 (함정)
