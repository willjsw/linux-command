# Linux Command Vault

**실사용·검증한 리눅스 명령어만 축적하는 Obsidian 지식 저장소**

일반 리눅스 명령어 레퍼런스가 아님. man page 를 옮겨 적은 문서가 아니라, **실제 작업 중 실행하고 결과를 확인한 명령어**와 **그 과정에서 겪은 함정**만 남기는 저장소.

---

## 왜 이런 방식인가

| 일반 명령어 정리 | 이 저장소 |
| --- | --- |
| 모든 옵션 나열 | 실제 쓴 옵션 위주 |
| 문법 설명 중심 | **실패 원인·함정 중심** |
| 가상 예시 (`file.txt`) | 실제 사용값 (용도 주석 포함) |
| 검증 여부 불명 | `verified` 필드에 검증 환경 명시 |
| 추측·전언 포함 | **미검증 항목은 `※ 미검증` 표시 의무** |

핵심 원칙은 **"추측으로 문서를 늘리지 않음"**. 쓰지 않은 명령어는 문서를 만들지 않고, 검증하지 않은 옵션은 표시 없이 기재하지 않음.

---

## 문서 구조화 시스템

### 1. 4계층 구조

```
Linux-Command/
├── README.md                   ← 본 문서 (저장소 소개)
├── SKILL.md                    ← 작성·갱신 규칙 (정본)
├── INDEX.md                    ← 색인 (MOC) + 작업 시나리오
└── <CATEGORY>/<command>.md     ← 개별 명령어 문서
```

- **SKILL.md** — 문서를 어떻게 쓸지 정의한 규칙서. 새 문서 작성 시 이 규칙을 따름
- **INDEX.md** — 전체 목록 + **작업 시나리오별 명령어 흐름**. 명령어 이름을 모를 때 진입점
- **`<CATEGORY>/`** — 명령어 사전. 개별 명령어 상세

### 2. 카테고리 (10개)

| 디렉터리 | 범위 |
| --- | --- |
| `PACKAGE-MANAGEMENT` | 패키지 설치·갱신·검증 |
| `NETWORK-MANAGEMENT` | IP·라우팅·원격접속·포트·HTTP |
| `DISK-STORAGE` | 디스크·파티션·LVM·마운트 |
| `USER-PERMISSION` | 계정·그룹·권한 |
| `SERVICE-SYSTEMD` | 서비스·타겟·로그·재시작 |
| `PROCESS-MANAGEMENT` | 프로세스 조회·종료·백그라운드 실행·포트 점유 |
| `BOOT-RECOVERY` | 부트로더·레스큐·복구 |
| `SECURITY-SELINUX` | 방화벽·SELinux·감사로그 |
| `SYSTEM-INFO` | 로케일·시간대·명령 가용성·환경변수 |
| `FILE-TEXT` | 파일·텍스트 처리 |

- 파일명은 **명령어 원문 소문자** (`dnf.md`, `nmcli.md`)
- 하위 명령이 많으면 단일 파일에 `## <명령> <서브명령>` 으로 분리 (`dnf.md` 내 `## dnf install`)
- 성격이 유사한 단순 명령은 통합 (`file-ops.md` = `mkdir`/`cp`/`mv`/`rm`/`touch`/`ln`/`chmod`)

### 3. 태그 체계 — 횡단 검색의 핵심

카테고리는 명령어를 **한 곳에만** 배치하지만, 실제 작업은 카테고리를 넘나듦. 태그가 그 연결을 담당.

문서당 **최소 5개**, 6계열 조합:

| 계열 | 용도 | 예시 |
| --- | --- | --- |
| `linux/*` | 기능 계열 (1개 이상) | `linux/network` `linux/text` `linux/process` |
| `task/*` | 작업 목적 (1개 이상) | `task/diagnose` `task/verify` `task/search` |
| `topic/*` | 주제 (1개 이상) | `topic/port` `topic/encoding` `topic/regex` |
| `privilege/*` | 권한 요건 (**1개 필수**) | `privilege/root` `privilege/user` `privilege/mixed` |
| `danger/*` | 위험도 (해당 시 필수) | `danger/destructive` `danger/data-loss` |
| `distro/*` | 배포판 한정 시 | `distro/rhel` `distro/rocky` |

**활용 예** — `#privilege/root` + `#danger/destructive` 로 필터하면 "root 권한으로 실행하는 파괴적 명령" 목록 확보. 작업 전 위험 명령 사전 점검에 사용.

### 4. 링크 3중 배치 — 그래프 형성

Obsidian 그래프뷰·백링크가 실제로 동작하려면 링크가 **세 위치에 모두** 있어야 함.

```markdown
---
related: ["[[lsof]]", "[[kill]]"]      ← ① frontmatter (구조적 관계)
---

... 포트 점유 확인은 [[lsof]] 참조     ← ② 본문 맥락 링크

## 연관 명령어
- [[lsof]] : 포트 점유 프로세스 조회    ← ③ 말미 (연관 이유 명시)
```

**링크 방향 원칙:**

| 유형 | 예시 |
| --- | --- |
| 진단 흐름 (상위→하위) | `ssh` → `ss` → `firewall-cmd` |
| 선행 조건 | `dd` → `lsblk` (장치명 확인 필수) |
| 대체 수단 | `nmcli` ↔ `nmtui` |
| 후속 작업 | `lvextend` → `xfs_growfs` |

**A 가 B 를 링크하면 B 도 A 를 링크** (백링크 대칭). 미작성 문서 링크는 허용 — 향후 작성 대상 표시 기능.

### 5. 문서 본문 규격

````markdown
---
command: <명령어>          category: <카테고리>       aliases: [<별칭>]
tags: [<5개 이상>]         related: ["[[관련명령]]"]
distro: <적용 배포판>       verified: <검증 환경>       updated: <YYYY-MM-DD>
---

# <명령어>
- 한 줄 정의
- 어원: <축약어 원형>          ← 암기 아닌 이해를 위한 필수 항목
- 특징·전제 (권한, 패키지 등)

## <명령어> <서브명령>
```bash
<기본 문법>
# Examples
<실사용 예시>              # 주석으로 목적 명시
```
### 명령어 설명
- 사용 목적 / - 특이사항       ← 함정·주의사항이 실질 가치
### 옵션
- `-h` : 읽기 쉬운 단위 (**h**uman-readable)    ← 원형 단어 굵게

## 연관 명령어
- [[관련명령]] : 연관 맥락 명시
````

**문체는 개조식·명사형 종결 고정.** `~합니다`/`~한다` 금지, `~ 시 사용`/`~ 필요`/`~ 발생` 사용. 산문 단락 금지 → 불릿·표·코드블록만. 스캔 속도를 위한 제약.

## 현행화 방식 — 문서가 낡지 않게 유지하는 절차

이 저장소의 실질 가치는 **"현재도 맞는 정보"** 라는 신뢰. 이를 유지하는 규칙:

### 갱신 트리거

문서를 손대는 시점은 4가지로 한정:

1. **새 명령어 실행** → 신규 문서 생성
2. **기존 명령어의 새 옵션·서브명령 사용** → 해당 섹션 추가
3. **문서 내용이 실제 동작과 달랐음을 확인** → **즉시 수정** (최우선)
4. **범용적으로 빈출하는 미기재 옵션 발견** → 자체 보강 (아래 조건 충족 시)

### 검증 상태 관리

| 표기 | 의미 |
| --- | --- |
| 표시 없음 | 해당 환경에서 실제 실행·확인 |
| `※ 미검증` | 자체 보강 항목 — man page 근거는 있으나 미실행 |
| `verified: 미검증 (참조용)` | 전 항목 미검증 문서 |

`verified` 필드는 **실제 검증 환경 기준 유지** → 자체 보강으로 변경하지 않음. 검증 완료 시 `※ 미검증` 제거 + `updated` 갱신.

### 자체 보강 기준 (미사용 옵션의 선제적 기재)

무한정 확장을 막기 위한 게이트. **전 조건(AND) 충족 시에만** 기재:

- 해당 명령어 문서가 **이미 존재** (신규 문서 생성 근거로는 불가)
- 실무에서 **표준적으로 빈출**
- 배포판·버전 무관하게 **동작 안정**
- man page·공식 문서로 **근거 확인 가능**

**배제 (OR — 하나라도 해당 시 미기재):**

- 특정 버전·배포판 한정 동작 (기재 시 태그·특이사항에 버전 명시)
- **`danger/*` 명령어의 미검증 옵션** → 파괴적 작업은 실검증 후에만
- 사용 빈도 낮은 특수 목적 옵션
- 동작 결과를 근거로 단정 불가한 항목

| 예시 | 판정 | 근거 |
| --- | --- | --- |
| `df -i` (inode 조회) | ✅ | 표준 빈출, 비파괴 |
| `grep -E` (확장 정규식) | ✅ | 범용 표준 |
| `dd conv=noerror,sync` | ❌ | 파괴적 명령의 미검증 옵션 |
| `parted resizepart` | ❌ | 파괴적, 실검증 필요 |

### 품질 체크리스트

문서 작성·갱신 후 전 항목 확인 (상세: [SKILL.md](SKILL.md) 9장):

- [ ] frontmatter 전 필드 작성
- [ ] 태그 5개 이상, `privilege/*` 포함 / 위험 명령에 `danger/*`
- [ ] 전 서술 명사형 종결, 산문 단락 없음
- [ ] 어원 기재, 옵션에 원형 단어 굵게
- [ ] 링크 3중 배치 + 역방향 링크 추가
- [ ] `INDEX.md` 갱신
- [ ] 미검증 항목에 `※ 미검증` 표시
- [ ] 추정·불확실 동작 미포함

### 갱신 후 반영

문서 추가·수정 시 **Git 커밋 후 `main` 푸시**. 커밋은 문서 단위로 분리하여 변경 이력이 곧 지식 축적 이력이 되도록 유지. 커밋 컨벤션은 [SKILL.md](SKILL.md) 10장 참조.

## 사용 방법

### 명령어 이름을 아는 경우
`<CATEGORY>/<command>.md` 직접 조회, 또는 Obsidian 검색.

### 명령어 이름을 모르는 경우
[INDEX.md](INDEX.md) 의 **작업 시나리오별 경로** 진입. 상황에서 명령어로 역방향 도달:

- OS 설치 직후 초기 설정
- 부팅 실패 / 로그인 실패 복구
- 서비스 접근 불가 진단
- 디스크 용량 부족 대응
- 애플리케이션 기동·검증·종료 루프
- 포트 점유 충돌 해소 (`Address already in use`)
- 코드 정의 ↔ DB 스키마 대조
- 레거시 소스 조사 (EUC-KR·바이너리 혼재)
- 의존성 라이브러리 내부 확인

### 위험 명령 사전 점검
태그 페인에서 `#danger/destructive` `#danger/irreversible` 필터.

### 플랫폼 차이 확인
[INDEX.md](INDEX.md) 의 **플랫폼 차이 주의 문서** 섹션 — GNU(Linux) ↔ BSD(macOS) 간 문법·동작이 다른 명령 집약. `sed -i`, `stat -c`↔`-f`, `wc` 공백 패딩, `timeout`↔`gtimeout` 등.

## Obsidian 환경

- 백링크·그래프뷰·태그페인 활성 전제
- `bases` 코어 플러그인으로 frontmatter 기반 동적 테이블 구성 가능 (예: `privilege/root` 필터, `updated` 기준 정렬)
- Obsidian 없이도 동작 — 일반 Markdown 이며 위키링크는 상대 경로 파일명 참조

`.obsidian/` 의 개인 UI 상태·플러그인 설정은 `.gitignore` 처리 → 문서 내용만 버전 관리.
